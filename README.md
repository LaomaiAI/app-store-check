# App Store 上架合规自查

粘贴 App 名称、描述、订阅价格、权限说明,10 秒逐项对照苹果审核条款出自查报告与修复清单。纯静态页,无登录、无后端、无模型调用。

## 一句话

不用读英文 playbook、不用装 Skill、不用跑脚本,打开网页粘贴上架资料,10 秒出逐项自查报告与修复清单。

## 用法

1. 打开 `index.html`(双击即可,或用任意静态服务器)。
2. 粘贴 App 名称、副标题、描述、订阅与内购说明、权限与隐私说明、隐私政策链接。
3. 勾选第 2 步人工核对清单里已确认的项。
4. 点"开始自查"(或按 Ctrl/Cmd + Enter)。
5. 看报告:评分、度量、35 项确定性检查(带证据原文与修复建议)、11 项人工核对结果。
6. 导出:复制报告(Markdown)、下载报告(.md)。

## 确定性检查(35 项,全部本地算出)

| 类别 | 项数 | 内容举例 |
|---|---|---|
| 元数据 | 12 | 名称超 30 字符、名称含免费与价格、名称含其他平台名、占位与测试字样、病毒扫描宣传、传感器冒充医疗测量、内购未在描述里披露、无法验证的断言、副标题含价格、站外购买引导、名称堆关键词、描述说免费但订阅标价 |
| 订阅与内购 | 8 | 订阅缺自动续订说明、描述与订阅价格不一致、试用缺天数与到期收费、订阅周期短于 7 天、发帖邀请换权益、挖矿与任务换币、抽奖开箱缺概率公示、订阅缺取消方式 |
| 隐私与权限 | 9 | 缺隐私政策链接、链接格式无效、权限用途含糊、申请通讯录短信等敏感权限、广告标识未先征得同意、第三方共享未披露、强制登录、面向儿童含第三方广告、缺 App 内注销入口 |
| 内容与设计 | 6 | 第三方平台内容下载、网站套壳、借用商标与苹果背书、低俗赌博内容、用户发内容缺过滤举报拉黑、缺联系方式 |

## 人工核对(11 项,本页不判定)

真机测试、演示账号与后端在线、内购可见可买、截图展示实际使用界面、预览为真实录屏、年龄分级如实填写、隐私标签与实际收集一致、恢复购买入口、账号注销入口、UGC 四件套、联系方式可找到。

## 评分

满分 100,不通过扣 10 分,警告扣 4 分;90 分以上 A,75 分以上 B,60 分以上 C,其余 D。评分只反映确定性检查结果。

## 规则依据

- Apple《App Store Review Guidelines》官网(developer.apple.com/app-store/review/guidelines/),核对日期 2026-11-27,条款编号以官网为准。
- 参考开源仓库 mjmirza/app-store-compliance(英文 playbook,125 条被拒模式,2026-11-20 约 1,819 star、单日 +377,至 2026-11-27 已 7,144 star),本工具为独立实现的中文网页版,与该仓库无代码关系。
- 做法同已上线的 AI 代码验收报告:静态页加确定性规则库,确定性检查与人工判断分开写清。

## 隐私

纯静态页面,无后端、无统计,粘贴的内容只在你的浏览器里运行,关闭页面即消失。

## 局限

- 只检查粘贴的文字,查不了二进制、截图、后端服务与真实运行表现。
- 通过自查不等于过审,最终以苹果审核结果为准。
- 否定表述的识别有限(目前只在通讯录、短信、通话记录这条上处理了"不收集"这类否定),其余规则按字面匹配。
- 规则会随苹果官网更新而过时,条款编号以官网为准。

## 测试

`npm test`(即 `node test/checker.test.js`):合格示例 100 分 A、问题示例 0 分 D、空输入、名称 30/31 字符边界、订阅 3 天与 7 天边界。

纯静态文件,直接推 GitHub Pages 即可,演示地址规划为 `https://laomaiai.github.io/app-store-check/`。
